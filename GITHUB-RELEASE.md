# DC Coms GitHub Release Procedure

Do not publish historical production repository or checkpoint history. The public repository must begin from the sanitized Community source tree.

Recommended repository name: `dc-coms`.

Before Git initialization:

```bash
./deploy/scripts/release-audit.sh
```

Expected: `DC Coms Community release audit: PASS`.

Create new history only from the sanitized tree:

```bash
git init -b main
git status --short
git add .
git status --short
```

Inspect staged files before committing. Do not proceed if generated secrets, runtime databases, backups, signing keys, TLS keys, or production configuration appear.

Initial commit:

```bash
git commit -m "Initial DC Coms Community release"
```

Create an empty GitHub repository with no generated README/license, add the GitHub-provided remote, and push:

```bash
git remote add origin <repository-url>
git push -u origin main
```

Recommended repository protections include protected `main`, review before merging, dependency alerts, secret scanning where available, private vulnerability reporting, and no force pushes to `main`.

For RC2, attach the `.tar.gz`, `.sha256`, and `.manifest.txt` generated by the release builder.

Do not publish final `1.0.0` until source audit, packaged-artifact audit, fresh Rocky 9 install, browser regression, service regression, security regression, backup verification, and recovery validation are complete.
